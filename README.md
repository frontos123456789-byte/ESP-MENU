# What do websites know about me?

Одностраничный инструмент самопроверки на **Next.js App Router, TypeScript и Tailwind CSS**. Показывает данные, доступные обычному сайту без регистрации и без запроса разрешений: IP/Geo/HTTP-заголовки, Client Hints, экран, локаль, GPU, отпечатки, сетевые интерфейсы, устройства и возможности браузера.

## Запуск

Требуется Node.js 22+ (рекомендуется 24).

```bash
npm ci
npm run dev
```

Откройте `http://localhost:3000`. На localhost IP и Geo Vercel обычно отсутствуют; часть API требует HTTPS. Для production:

```bash
npm run build
npm start
npm test
```

Прямой запуск тестов: `npx tsx --test tests/privacy.test.ts`.

## Деплой на Vercel

1. Загрузите проект в свой Git-репозиторий и импортируйте его в Vercel.
2. Выберите Next.js, корень проекта, Node.js 24.x. Build command: `npm run build`; install command: `npm ci`.
3. Для основных функций переменные окружения не требуются. Не подключайте Analytics, Speed Insights, Log Drains или сторонние скрипты.
4. Выполните Deploy. Для самостоятельного CLI-деплоя после настройки авторизации: `npx vercel --prod`.
5. Откройте HTTPS URL, проверьте `/api/whoami`, затем сравните результаты с включённым и выключенным VPN.

Приложение не использует cookies, localStorage, IndexedDB, базу данных или серверные логи приложения. Результаты находятся в React state и исчезают при закрытии/перезагрузке страницы. JSON скачивается непосредственно браузером. `/api/whoami` получает IP и заголовки, запрашивает IP-обогащение и возвращает результат с `Cache-Control: no-store`; запросы/ответы не сохраняются кодом приложения. Vercel, ваш reverse proxy и внешние провайдеры могут обрабатывать технические журналы по своим политикам: приложение не может гарантировать отсутствие инфраструктурных логов. Отключите доступные логи/дренажи в инфраструктуре, если это необходимо.

## Структура

- `app/page.tsx` — прогрессивный single-page UI, поиск, экспорт, повторный скан.
- `app/api/whoami/route.ts` — IP из `x-vercel-forwarded-for` / `x-real-ip` / `x-forwarded-for` (с очисткой порта), служебные подписи Vercel скрываются, Geo Vercel, все доступные приложению HTTP-заголовки, IP-обогащение.
- `app/api/network/route.ts` — небольшие запросы задержки, download до 2 MiB, upload до 512 KiB, без хранения тела запроса.
- `app/api/dns/route.ts` — необязательный прокси к авторитетному DNS-сервису; токен остаётся на сервере.
- `collectors/*.ts` — независимые сборщики с обработкой ошибок, таймаутами и статусами.
- `lib/types.ts` — типы полей, секций и privacy findings.
- `lib/privacy.ts` — детерминированный fingerprint и объяснимые эвристики отчёта.
- `dns-service/` — необязательный отдельный DNS-сервис с кратковременной памятью.
- `tests/privacy.test.ts` — проверки отсутствующих данных, адресов, возможных утечек и стабильности fingerprint.

## Что собирается

**Browser:** UA, vendor, language(s), platform, cookieEnabled, DNT, GPC, PDF viewer, webdriver, CPU threads, deviceMemory, touch points, low/high entropy Client Hints.

**Screen/locale:** размеры экрана и окон, DPR, VisualViewport, orientation, цветовая глубина, HDR/gamut, preference/pointer media queries; Intl options, timezone и UTC offset.

**GPU/fingerprint:** WebGL/WebGL2 параметры, расширения, debug vendor/renderer; WebGPU adapter info при наличии; SHA-256 canvas, реально отрисованных WebGL пикселей и OfflineAudioContext; эвристический поиск более 200 шрифтов, speech voices, plugins/MIME types. Итоговый SHA-256 имеет версию схемы и не включает IP, текущее время, скорость и другие заведомо изменчивые измерения.

**Network:** HTTP IP/Geo/headers, отдельные IPv4/IPv6 запросы, ICE/STUN-кандидаты, Network Information API, `PerformanceResourceTiming.nextHopProtocol`, отдельный HTTP speed test.

**Device:** батарея, storage estimate/persisted, enumerateDevices, статусы известных permissions, наличие интерфейсов сенсоров, gamepads, Bluetooth/USB/Serial/HID, keyboard layout, H.264/VP9/AV1/HEVC/AAC decoding capabilities.

**Behavior:** локальный bait для косметических adblock-фильтров, Brave self-identification, артефакты автоматизации и защиты от fingerprinting. Никакого запроса камеры, микрофона, геолокации, локальных шрифтов, USB/Bluetooth или активации сенсоров. Permissions API только читает статус. Permissions-Policy страницы запрещает только камеру, микрофон и геолокацию (страница их не использует), поэтому `denied` для них может отражать эту политику; статусы сенсоров показываются как есть.

## Внешние соединения

| Получатель                            | Для чего                   | Какие данные видит                                             |
| ------------------------------------- | -------------------------- | -------------------------------------------------------------- |
| Vercel / хост приложения              | Страница, API и speed test | IP, HTTP-заголовки и технические метаданные запроса            |
| `ipwho.is`                            | Серверное обогащение IP    | Публичный IP посетителя в URL, IP сервера приложения           |
| `api.ipify.org`                       | IPv4-only проверка         | IPv4 и обычные заголовки запроса                               |
| `api6.ipify.org`                      | IPv6-only проверка         | IPv6 и обычные заголовки запроса                               |
| `stun.l.google.com:19302`             | WebRTC ICE                 | Сетевой адрес STUN-клиента                                     |
| Собственный DNS-сервис, если настроен | Активный DNS-тест          | Случайные имена и IP рекурсивных резолверов, временно в памяти |

Внешних JS-скриптов, трекеров и аналитики нет. Отпечатки не отправляются провайдерам или серверу приложения. `dnsleaktest.com` — обычная внешняя ссылка; переход выполняет пользователь. Тест скорости — отдельное действие, около 2.5 MiB трафика плюс накладные расходы.

## Как читать Privacy report

- **Зелёный:** конкретная проверка не обнаружила рассматриваемого расхождения. Не означает полную анонимность.
- **Жёлтый:** неоднозначный признак, который стоит сравнить с настройками VPN.
- **Красный:** доступно много fingerprint-сигналов либо WebRTC показывает отличающийся публичный IP того же семейства. Требуется проверка контекста.
- **Неизвестно:** данных нет, API заблокирован, проверка не настроена или вывод объективно невозможен. Это не успешная проверка.

Privacy Score 0–100 — локальная эвристика доступности сигналов. Рядом показывается покрытие проверок. Неизвестные проверки не уменьшают score, поэтому высокий score при низком покрытии не означает защищённость. Штрафы определены в `lib/privacy.ts`: WebRTC 30, HTTP routing 8, timezone 5, language 3, IPv6 8, fingerprint 25; для жёлтого уровня применяется половина соответствующего штрафа. Сам факт использования VPN не является нарушением приватности.

«Условные биты» рассчитываются по явным весам признаков, без базы посетителей. Это **не измеренная энтропия Шеннона, не вероятность идентификации и не оценка уникальности относительно популяции**. Коррелирующие признаки, антифингерпринтинг, рандомизация и ограничения браузера влияют на результат. Достоверная популяционная уникальность потребовала бы внешней базы, что противоречит цели не хранить данные.

### Ограничения браузера и сети

- Route handler за Vercel видит HTTP-запрос после прокси. Исходную HTTP/2 или HTTP/3 нельзя достоверно восстановить из него; используется Resource Timing. Пустой протокол может быть следствием ограничений API или отсутствия `Timing-Allow-Origin`.
- Geo-IP приблизителен. `x-forwarded-for` доверяется только за вашим доверенным ingress/Vercel; при самостоятельном хостинге настройте перезапись заголовков прокси.
- Бесплатный IP API может не отдавать VPN/proxy/hosting/Tor-флаги, ограничивать частоту или быть недоступным; отсутствие флагов означает «неизвестно».
- `api64.ipify.org` является dual-stack и не доказывает IPv6-доступность. Здесь используется настоящий IPv6-only `api6.ipify.org`.
- Разные IPv4/IPv6 — нормальное явление; их нельзя сравнивать как один адрес. Доступный IPv6 не равен утечке: сравните его с ожидаемым egress VPN.
- Другой WebRTC-IP может означать split tunneling, прокси или несколько интерфейсов. Отсутствие ICE-кандидатов может означать блокировку STUN.
- Инкогнито, Tor Browser и Firefox resistFingerprinting нельзя достоверно определить такими эвристиками. Storage quota не доказывает приватный режим. Incognito также не скрывает IP.
- Язык без явного региона (`en`) не превращается автоматически в страну. Отличие языка от IP-страны не доказывает VPN.
- Скорость — одна ограниченная HTTP-передача с серверными накладными расходами; ping здесь HTTP RTT, jitter — средняя абсолютная разность соседних RTT. Это не ICMP и не предельная пропускная способность линии.
- Keyboard layout/WebGPU/media devices могут быть недоступны без жеста, разрешения или из-за политики браузера. Показаны ошибки/«не поддерживается», а не фиктивные значения.
- Экспорт содержит IP, заголовки и другие чувствительные значения. Проверьте JSON перед отправкой другим людям; cookies/authorization, если они попали в запрос, также могут присутствовать среди заголовков.

## Необязательный DNS-тест и wildcard-домен

**Один wildcard A/CNAME на Vercel не позволяет узнать DNS-резолверы.** HTTP-запрос показывает HTTP-клиента; запрос от рекурсивного DNS виден только вашему авторитетному DNS-серверу. Vercel Functions не обслуживает входящие UDP/TCP 53. Поэтому сервис ниже запускается отдельно, например на маленьком VPS с публичным IPv4. Без него UI показывает инструкцию и ссылку на dnsleaktest.com.

### 1. Делегируйте тестовую DNS-зону

Используйте собственный домен, например `dnscheck.example.com`. В родительской зоне `example.com` создайте:

```text
dnscheck       NS  ns1.dnscheck.example.com.
ns1.dnscheck   A   <PUBLIC_IPV4_OF_VPS>
```

Провайдер DNS должен поддерживать делегирование дочерней зоны. Адрес NS должен быть доступен как glue при необходимости. Не ставьте обычную wildcard CNAME на Vercel вместо NS: это не передаст наблюдение DNS-запросов сервису. Для надёжности production рекомендуется второй авторитетный NS; приведённый минимальный сервис использует один хост и предназначен для личной диагностики.

Сервис динамически отвечает на восемь случайных имён вида `<32-hex-session>-0.dnscheck.example.com` … `-7`. Это выполняет роль тестового wildcard, но неизвестные имена не принимаются. Отдаётся только A, AAAA/HTTPS получают NODATA. Кеширование ответов отключено (`TTL=0`), рекурсия запрещена.

### 2. Запустите companion

```bash
cd dns-service
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
```

Настройте в защищённом окружении сервиса (не коммитьте секреты):

```text
DNS_TEST_DOMAIN=dnscheck.example.com
DNS_TEST_IPV4=<PUBLIC_IPV4_OF_VPS>
DNS_TEST_TOKEN=<random-secret-at-least-32-characters>
DNS_PORT=53
HTTP_HOST=127.0.0.1
HTTP_PORT=8053
```

Запуск: `python server.py`. Для привязки к порту 53 предоставьте процессу минимально необходимую возможность bind-service либо используйте перенаправление порта; не запускайте весь сервис с необязательными привилегиями. Откройте входящие **UDP и TCP 53**. HTTP API по умолчанию доступен только на localhost.

Сервис не пишет query/access logs, не использует диск/БД и хранит до 256 сессий, до 64 резолверов на сессию. Наблюдения автоматически очищаются в течение 60 секунд, также удаляются после перезапуска. Во время теста это сознательное исключение из правила «всё в браузере», необходимое для DNS-измерения; модуль отключён по умолчанию.

### 3. Защитите API HTTPS

Поставьте HTTPS reverse proxy перед `127.0.0.1:8053` на отдельном имени, например `dns-api.example.com`, с действительным TLS-сертификатом. Отключите access/error logging запросов в proxy и сервисном менеджере, не записывайте Authorization. Приложение передаёт bearer-токен только server-to-server. Настройте ограничение частоты запросов на ingress для публичного `/api/dns` и DNS-сервиса согласно ожидаемой нагрузке.

Тестовые HTTPS-запросы к восьми случайным именам нужны для запуска DNS-резолвинга; HTTP-ответ не анализируется. Валидный wildcard TLS-сертификат `*.dnscheck.example.com` и ответ 204 на `/probe` улучшат совместимость, но даже неуспешное HTTPS-соединение обычно уже вызывает DNS. Если добавляете такой endpoint, отключите его access logs. Браузер, прокси или защитное ПО всё равно могут не выполнить DNS: пустой результат остаётся неопределённым.

### 4. Настройте Vercel

Добавьте в нужное окружение проекта и выполните redeploy:

```text
DNS_TEST_ORIGIN=https://dns-api.example.com
DNS_TEST_TOKEN=<тот-же-секрет>
```

Ни одна из переменных не должна иметь префикс `NEXT_PUBLIC_`. Вручную проверьте делегирование (`dig NS dnscheck.example.com`), затем запустите DNS-тест в UI. Будут показаны IP рекурсивных резолверов и типы наблюдённых запросов. Сравните их с ожидаемыми резолверами VPN. DoH, shared resolvers и forwarding означают, что адрес наблюдаемого DNS не всегда принадлежит вашему ISP; автоматический вывод «утечка» не делается.

HTTP API companion: `GET /start` → `{ id, hosts, expiresIn }`; `GET /result?id=...` → `{ resolvers, observedResolvers, expiresIn, interpretation }`. Оба запроса требуют `Authorization: Bearer ...`. Результат одной сессии нельзя получить без её случайного 128-битного идентификатора и серверного токена.

## Безопасность и ограничения

- `next.config.ts` задаёт CSP (скрипты и стили только с собственного origin, `frame-ancestors 'none'`), `Referrer-Policy: no-referrer`, COOP и запрет кэширования.
- `/api/whoami` и `/api/network` имеют простой in-memory rate limit на IP (12 и 60 запросов в минуту). Это best-effort: инстансы serverless не делят память. Для жёсткой защиты включите правило Rate Limiting в Vercel Firewall.
- Страница помечена `noindex`: это личный инструмент, а бесплатное IP-обогащение (ipwho.is) имеет месячную квоту.
- Если ipwho.is не возвращает security-флаги (бесплатный тариф), отчёт использует эвристику по названию оператора (VPN/хостинг) и явно помечает её как эвристику.
